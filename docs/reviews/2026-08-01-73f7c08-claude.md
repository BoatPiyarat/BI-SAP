## BLOCK 1 — CONFIRMED: the two source views cannot be UNION ALL'd with `SELECT *`

048's `_payload_source` does `SELECT * FROM fully_paid UNION ALL SELECT * FROM installment`.
Reproduced standalone (0-byte dry-run, 2026-08-01): **`Column 22 in UNION ALL has incompatible
types: STRING, DOUBLE`** — position 22 is `GrossPremium`, the first of the 22 known type-drift
positions (RQ-2330), which drift *between these two views*. 048 is a procedure, so its file-level
dry-run is blind (standing late-binding lesson); the CALL fails at the first payload statement.
**Fix:** project all 56 columns explicitly in each branch with harmonized types (e.g. `SAFE_CAST(...
AS FLOAT64)` on the money/quantity drift positions, or CAST-to-STRING uniformly) *before* the
UNION. Bonus: the winner hash then fingerprints normalized payloads, so equal values from the two
views can no longer hash differently merely because of type rendering.

## BLOCK 2 — G3 is skipped: straight to production `RCB_MOTOR` with no UAT2 pass

Neither 049 nor the runbook (RQ-2243) contains a UAT2 step. CURRENT_STATE §7 G3: dry-run one file
set into **UAT2 before production, always — ห้ามข้าม**. It matters concretely here, not
ceremonially, because the legacy serializer is **unknown** (RQ-2330 ground-truth limits) and 049
introduces at least three unverified physical-format choices: `header=true` (header presence in
SAP-consumed files is explicitly unverified), EXPORT DATA's CSV quoting (e.g. commas in
`BillingAddress`), and NULL money fields rendering as empty rather than `0.00`
(`FORMAT('%.2f', NULL)` → NULL — verified earlier today). **Fix:** run the identical mechanism
against the UAT2 path first with a known-answer field-level compare on the 22 drift positions +
header/quoting acceptance, per the RQ-2330 review note — or record Boat's explicit written waiver
of G3.
