## Required Note — one report's failure silently strands every other pending report in the same batch

`dispatchPendingV3DailyCompletenessReports` (line 17) calls
`pending.forEach((row) => deliverV3DailyCompletenessReport_(config, row.f[0].v))` with no try/catch
around each call. Tracing `deliverV3DailyCompletenessReport_`'s catch block to its end: even when
the fallback send *succeeds*, the function still `throw`s a final `COMPLETENESS_ALERT_FAILED` error
after the fallback branch — by design, so the primary-channel failure itself is surfaced, not
swallowed. But because this throw is not caught inside the `forEach`, it propagates out and aborts
the loop entirely: **any other pipeline run still `PENDING` in that same `pending` array — completely
unrelated to whichever run's primary mail failed — never gets processed in this dispatch run.**

This is the same class of "one bad item stops the batch" pattern I accepted as non-blocking in the
Unit 6 ingestion runtime (`docs/reviews/2026-08-04-1e949e7-claude.md`), but the retry economics are
materially worse here: the ingestion poller re-fires every ~15 minutes, so a stranded item is
picked up again shortly. This dispatcher is named and scoped as a *daily* report — if its trigger
is installed at a roughly daily cadence (the deployment doc doesn't pin an interval), a stranded
report could sit `PENDING` for a full day before the next attempt, silently, in a system whose
entire purpose is giving Boat reliable visibility into pipeline completeness. Nothing is ever
permanently lost (the row stays `PENDING` and will be retried on the next dispatch), but the delay
undermines the alerting system's own promise more than the ingestion poller's equivalent case does.

**Fix required before deploy:** wrap each `deliverV3DailyCompletenessReport_` call in its own
try/catch inside the `forEach`, so one run's primary/fallback failure doesn't prevent the others in
the same batch from being attempted — collect failures and rethrow/aggregate once at the end if you
still want the overall dispatch run to surface as failed for Apps Script's own exception logging.
