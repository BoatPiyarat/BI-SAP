## Implemented source

- `032`: exact E2 values `test` and `test div`; E3 master seed comes from non-empty
  `SAP_LIVE_FULL.U_InsurerCode` rows with positive, non-NULL `DocEntry`. Insurer codes are
  canonicalized across both SAP's prefix form (`prefix-code`) and CareOS's path form
  (`resource/code`).
- `036`: F1 now maps both NULL and trimmed empty InsuredID to `-` in the incremental source and
  full backfill.
- `037`: E1 tier uses `OrderDate` only, while processing keeps
  `GREATEST(OrderDate, PolicyDate)` separately. <=2024 uses `YEAR_OUT_OF_SCOPE`; 2025 is retained
  only for an already-posted, effectively cancelled order; other 2025 rows use
  `YEAR_2025_NON_CANCEL_EXCLUDED`. E2 uses exact normalized first/last-name matching and
  `TEST_CUSTOMER`. E3 uses `INSURER_NOT_IN_MASTER`. Every applicable exclusion is written to
  `sap_excluded_records`; no export-layer drop was added.
- `035`: F2 blocks PolicyNo longer than 50 without truncating or echoing the PolicyNo into the
  validation detail. F3 validates all five date columns in the verified 56-column contract
  (`OrderDate`, `PolicyDate`, `PaymentDate`, `ExpectedDate`, `BatchRunDate`) across all 12 live
  interface flows with the locked predicate: empty, or exactly 8 characters parseable as
  `%d%m%Y`.
- `046`: morning view keeps exclusions, validation errors, and real backlog in separate sections;
  it includes the distinct/listed insurer-code signal and PII-free F2/F3 examples.

No procedure/view/table was deployed, called, refreshed, exported, or mutated by this work.
