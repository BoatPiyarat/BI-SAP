## Required note — the push-subscription readiness check verifies only the subscription's *name*, not its actual push configuration

`$pushSubscription = @($subscriptions | Where-Object { $_.name -eq
"projects/$project/subscriptions/$pushSubscriptionName" })`, and the only gate on it is
`$pushSubscription.Count -ne 1`. This checks that *a* subscription with the expected name exists —
it never inspects `pushConfig.pushEndpoint` (should point at the dispatcher's URL) or
`pushConfig.oidcToken.serviceAccountEmail` (should be the push service account). If a subscription
were ever created with the right name but a wrong or missing push endpoint, or a pull subscription
with no `pushConfig` at all, this checker would report `rehearsal_ready` progress on that item as
satisfied when messages still could not reach the dispatcher. This is exactly the
false-positive-risk category the request asks to review.

This does not corrupt anything and would very likely be caught immediately by the mandatory
synthetic rehearsal itself (already reviewed in RQ-1956 — its first case, "one event creates one
CLAIMED → STARTED child execution," fails loudly if the push path is broken) — so it does not block
this review's PASS. But it should be fixed before this checker is treated as a sufficient go/no-go
signal on its own: add a check that `pushConfig.pushEndpoint` matches the dispatcher's URL and
`pushConfig.oidcToken.serviceAccountEmail` matches `$pushServiceAccount`.

## Minor observation (not blocking)

The `delivery_enabled: false` and `sp_reconcile_v3_post_import_rows` safety checks are plain
substring/regex matches against the whole workflow source text (`$workflowSource -notmatch ...`).
This doesn't distinguish a live, uncommented assignment from the same string appearing in a comment
elsewhere in the file. Currently harmless (the live source has exactly one occurrence of each,
confirmed in this session's earlier reviews), but a future source edit that added a second,
commented-out or contradictory occurrence could produce a false pass. Not required before this
review's PASS given the file's current, already-reviewed content.
