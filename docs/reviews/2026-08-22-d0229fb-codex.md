# Review: RQ-20260822-1147 urgent-refund cancel candidate

Reviewer: Codex  
Artifact: `d0229fb` plus correction commit `9803f4e`  
Verdict: **BLOCK**

The source must not be executed or exported. Blocking findings:

1. Pending rows forward-fill `PaymentMethod` and `PaymentChannel` from the Paid period. Boat's
   2026-08-22 Aware answers require both fields to be blank on every Pending predecessor row.
2. It does not reconcile each SAP Pending period to CareOS successful payment truth. The confirmed
   sequence requires a separate Paid/new-payment file and SAP Paid acknowledgement before cancel.
3. It does not exclude membership on either side of `careos.cancelled_change_orders`, so a linked
   item can be misrouted into plain cancellation.
4. It does not require `sap_mirror_state.docs_considered=1`; an unresolved multi-document winner
   can be silently cloned despite the canonical unresolved-rule gate.
5. `urgent_refund_cancel_ready` defines all 56 payload values as STRING (plus `request_id`), which
   does not match the live 56-column physical contract's numeric and integer types. No ordinal/type
   equality assertion compares the export projection to the live contract.
6. The NULL gate treats `PendingPayment` NULL as blocking even though Aware confirmed that field
   may preserve SQL NULL, while exempting `PaymentDate`/`InvoiceNo` without constraining those
   exceptions to rows whose predecessor was Pending. The predecessor status is not retained.
7. Source predecessor status is never asserted to the exact Paid/Pending vocabulary and Paid rows
   are not required to retain nonblank immutable InvoiceNo and PaymentDate.
8. The candidate hash includes a run-date-derived `BatchRunDate`, so it is not stable across build
   and later export unless the exact immutable rows are persisted and the exporter binds to their
   manifest. No reviewed exporter exists.

Independent replacement evidence in `bc25b32` is not part of this verdict. It produced a temporary
47-row / 6-item candidate with hash `5eef984f...c4027`, added CareOS-payment, change-order,
single-document, predecessor-status, spine, and Paid-identity gates, and is separately awaiting
