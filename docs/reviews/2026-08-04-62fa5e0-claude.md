## Note (non-blocking, shared pattern across 058/059/069)

The period-spine check (`COUNT(DISTINCT Period) = TotalPeriods` + `MIN(Period) = 1`) proves
cardinality and a correct start, but not that the specific range `1..TotalPeriods` is present with
no gaps — e.g. periods `{1, 2, 4}` with a stated `TotalPeriods=3` would satisfy `period_n=3=total_n`
despite genuinely missing period 3. This is not new to `069`: the identical check exists in `058`
and `059` and was already accepted under prior review (RQ-1818). Flagging because `069` is the first
*human-scoped* (not nightly-batch) caller of this pattern, where an unusual manual OrderItem
selection is more likely to hit an edge case the automated path wouldn't naturally produce.
Recommend a follow-up hardening pass across all three files (e.g. compare against
`GENERATE_ARRAY(1, total_n)`) rather than blocking this file alone for an inherited pattern.

## Note (non-blocking but **recommend fixing before deploy**): `requested_by` is validated, never persisted

`p_requested_by` is asserted non-empty (line 29–30, "Manual export requires requested_by audit
identity") but is **never written anywhere** — not into `export_archive` (whose full column list,
confirmed by reading `048`'s `CREATE TABLE`, has no `requested_by`/`approved_by`/similar field), not
into `payload_json` (`TO_JSON_STRING(p)` serializes only the delivery-ready payload row, not the
procedure's own parameters), and not into any other table this procedure touches. The parameter is
validated as present and then silently discarded. As written, there is no way to determine *who*
triggered a given manual export from `export_archive` after the fact, despite the file's own stated
intent to require an "audit identity." This doesn't affect the correctness or safety of the export
itself (it's a governance gap, not a data-integrity one), so it doesn't block this source-only
commit — but it should be closed (e.g. add a `requested_by` column to `export_archive`, or write a
row to a dedicated manual-export-request log) before this procedure is deployed and made callable,
or the "audit identity" requirement is cosmetic.
