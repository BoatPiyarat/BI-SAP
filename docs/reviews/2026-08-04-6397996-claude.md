## Note (non-blocking)

The pickup table explicitly disclaims itself ("never interpreted as SAP import success"), but the
symmetric claim — that a *terminal header* row (`attachment_parse_status='PARSED'` + matched
manifest) is still not row-level reconciliation ACK — is only implicit here, via "before any
downstream ACK consumer is deployed" (line 65). That boundary is stated explicitly in the sibling
runbook reviewed under RQ-20260803-1953 ("row-level reconciliation... remains a separate step"), so
the contract is not actually ambiguous across the two artifacts together — but a reader of this DDL
file in isolation could read a `PARSED` header as row-level-complete. Recommend adding one comment
line on the header table making that boundary explicit, matching the pickup table's style, before
this becomes the input to the future exact-manifest binding procedure.
