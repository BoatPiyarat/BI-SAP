## Note (non-blocking, deploy-sequencing)

`032`'s `CREATE TABLE IF NOT EXISTS` is a no-op against the already-live `sap_excluded_records`
table — BigQuery does not alter an existing table's schema on `IF NOT EXISTS`. The two new columns
only actually materialize when `037`'s `sp_refresh_expected_state` is deployed *and* subsequently
`CALL`ed, because its body uses `CREATE OR REPLACE TABLE ... AS SELECT` (which does regenerate
schema from the query). This isn't a defect in the source — both files are consistent with each
other and with "no deploy occurred" — but whoever executes the eventual deploy should know that
`032` alone accomplishes nothing on its own against a live table; the real schema change ships with
`037`'s next successful CALL. Worth one line in the eventual deploy runbook/evidence entry so this
isn't rediscovered under time pressure.
