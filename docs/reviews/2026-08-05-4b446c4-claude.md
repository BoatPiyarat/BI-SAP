## Checked against the request's own checklist

- **PowerShell exit-code/error behavior**: `$ErrorActionPreference = 'Stop'` at the top; every
  precondition (`activation.ps1`, the SQL template, `bq_safe_query.sh`, Git Bash) is checked with
  `Test-Path` and throws with a specific message if missing. One minor observation, not blocking:
  the explicit `if ($LASTEXITCODE -ne 0) { throw ... }` after invoking the activation checker is
  likely unreachable dead code in the "activation script itself throws" case, since an uncaught
  terminating error from a child `.ps1` invoked via `&` propagates directly to this script's own
  scope rather than surfacing as a `$LASTEXITCODE` value — but the net effect (this script also
  fails closed) is identical either way, so it doesn't change the actual behavior.
- **Temporary-path conversion and cleanup**: `Convert-ToGitBashPath` correctly maps a Windows
  absolute path (`C:\...`) to Git Bash form (`/c/...`), rejecting anything that isn't a drive-rooted
  path. The substituted query is written to a `New-TemporaryFile`-created file, used inside a
  `try` block, and removed in `finally` regardless of success or failure — the nonce never persists
  beyond that temporary file.
- **Token-count/substitution safety**: counts occurrences of `__REPLACE_14_DIGIT_NONCE__` via

- **Activation JSON handling**: pipes the activation checker's JSON output through

- **SQL cardinality/three-valued-logic assertions — the key fix in this commit, verified
  precisely**: the SQL template (also modified here) now wraps the original `SELECT` in
  `CREATE TEMP TABLE _verification AS ...`, then asserts `COUNT(*) = 3` (catches a missing or
  duplicated case) and, critically, `COUNTIF(expected_final_state IS TRUE) = 3` — using `IS TRUE`
  rather than `= TRUE` correctly treats both `NULL` (missing evidence, traced in the RQ-2055 review)
  and `FALSE` (wrong state) as "not passing," and an `ASSERT` failure aborts the whole BigQuery
  script with a non-zero exit — which is exactly what `$LASTEXITCODE -ne 0` in the PowerShell
  wrapper then catches. Before this delta, the base SQL was a plain `SELECT` with no enforcement;
  now a rehearsal result that isn't exactly three all-`TRUE` cases genuinely fails the whole
  invocation, not just prints a result someone has to read.
- **Wrapper enforcement**: every BigQuery call goes through `scripts\bq_safe_query.sh` (invoked via
  Git Bash) — no direct `bq query`/`bq_safe_query.sh`-bypassing call exists anywhere in the script.
- **Absence of production mutation/workflow/GCS/SAP action**: the script only reads
  (`check_post_import_activation.ps1`, a temp SQL `SELECT`) and writes a local temp file it deletes
  itself — no `gcloud`/`bq` mutation command anywhere.
- **Independently reproduced the "live read-only negative test," not just read about it**: ran
