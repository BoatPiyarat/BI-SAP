# Class-A review — `da64485`

Reviewer: Codex, with independent Standards and Spec sub-reviews  
Verdict: **BLOCK**

## Standards

1. **HIGH — failed export can become a false healthy-zero retry.** DDL 060 writes
   `PREPARED_ARCHIVE` ledger rows before `EXPORT DATA`, while DDL 061 excludes that status from a
   later attempt. If export fails after the insert, retry can skip the identities although no
   archive object exists. This violates charge conservation and fail-closed replay behavior.
2. **MEDIUM — current-event view selects the wrong completion boundary.** DDL 083 chooses the
   latest successful `UNIT1_START`, not a run with completed Unit 5 evidence, so it can expose an
   empty, partial, or stale identity set.
3. **MEDIUM — file contract proof is incomplete.** A 56-column count and explicit select list do
   not prove exact ordinal names/types against the canonical contract. Dry-run evidence proves
   syntax/cost, not exact immutable-row or schema conservation.

## Spec

1. **CRITICAL — Unit 6 is incompatible with net-new ledger rows.** DDL 062 still compares archive
   rows with all current-run NEWPAYMENT identities. A 66-identity archive from a 559-identity run
   will fail its `v_archive_rows=v_identity_rows` assertion.
2. **CRITICAL — manifest count does not describe the object.** The archive ledger contains target
   event identities, but the CSV contains complete spines. DDL 062 records `data_row_count` from
   archive ledger rows, which cannot equal physical CSV rows for multi-period items.
3. **HIGH — identity claim is not atomic.** The anti-join, ledger insert, and export have no
   serialized claim/unique enforcement. Concurrent calls can select the same net-new identities
   and create two archives.

## Positive findings

- Standard SQL and NULL-safe anti-join.
- Explicit 56-field export order.
- No `gs://interface-file/**` write.
- The event-only diagnostic shape addresses the reported August visibility issue.

## Required rework

- Reconcile or fail closed on `PREPARED_ARCHIVE`; never classify it as delivered/archived without
  exact object metadata.
- Introduce an atomic, idempotent export claim.
- Make Unit 6 bind to the exact claimed net-new identity set.
- Persist both event-identity count and actual full-spine object row count.
- Bind the operator view to a completed Unit 5 run.
- Add exact ordinal/name/type and immutable-row evidence.
