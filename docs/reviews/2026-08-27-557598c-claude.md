  run guard.

  the final run INSERT, enclosing metric, evidence, and run writes.

  before it, which is valid for BigQuery multi-statement transactions.

  This is a source inference from documented BigQuery behavior, not a live failure injection in
  the review session.

## Non-blocking notes

   same `pipeline_run_id` could both observe zero before either commits. This is pre-existing, not
   introduced by `557598c`; the correction guarantees sequential retry safety, while the calling
   workflow must remain non-overlapping per run.
2. The regression checker is a meaningful RED/PASS signal for this exact defect but is a static
   string/position check, not a semantic SQL proof. It does not prove guard reachability or recheck
   the original run-table guard.
