## The triggering failure, and what it says about the prior PASS

`v3full_validation_20260802_015700` failed because live `sap_view.RCL_Motor_process_2_newpayment`
cannot parse its own internal position-56 UNION (STRING vs DATE). Two things worth recording:
(1) that view is exactly the one flagged **NO_BASELINE** in the drift inventory — no repo-level
review could have seen its internal defect, which is the drift-governance rule biting again;
(2) the deeper lesson the delta correctly draws is architectural: 035's design choice to *read*
legacy views at validation time imported legacy fragility into V3's chain. Removing every
`sap_view.*` dependency from V3's general validation is the right fix, not patching around one view.

## Coverage regression check — none that matters, one boundary made explicit

## UNPIVOT semantics — correct as written

BigQuery UNPIVOT drops NULL values by default, so NULL dates never reach the assert's WHERE. That
is semantically right here, not a gap: the contract says a date is *empty or valid DDMMYYYY*, and
NULL renders as an empty CSV field — i.e. NULL is an allowed value, so excluding it from the
violation scan is exactly the intended behavior. No `INCLUDE NULLS` needed.
