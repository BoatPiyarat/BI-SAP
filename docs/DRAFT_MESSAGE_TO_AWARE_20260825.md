สวัสดีค่ะทีม Aware

รบกวนขอคำแนะนำเรื่องการบันทึกบัญชี AR ให้หน่อยค่ะ

**Background:** ทางทีม BI มีการรัน script แก้ไข order ที่เป็นการจ่ายเงินแบบ onetime ผ่านบัตรเครดิต/EDC จริง (payment_option = CREDIT_CARD_INSTALLMENT) แต่ข้อมูลฝั่ง CareOS ระบุ number_of_installment ผิดเป็น 6 หรือ 10 งวด (ทั้งที่จริงจ่ายครั้งเดียวจบ) — script นี้ force ให้ order เหล่านี้ถูกตีความเป็น onetime แล้ว interface เข้า SAP

**ปัญหาที่พบ:** เมื่อ interface เข้าไป ยอดที่ควรบันทึกเข้าบัญชี **1135-01 (AR Credit Card and Payment Gateway)** กลับไปบันทึกที่ **1134-01 (AR Installment - Motor)** แทนทั้งจำนวน พบแล้ว **141 orders ช่วง ก.ค.-ส.ค. 2569 รวมมูลค่า ฿1,640,393.50**

**ตัวอย่าง:**

| OrderItem | วันที่ | Payment Channel | ยอด (ExpectedReceived) | บันทึกบัญชีจริง |
|---|---|---|---:|---|
| L78667850-V1 | 2026-08-01 | RCB-EDC-KBANK | 14,470.68 | 1134-01 เต็มจำนวน ไม่มี 1135-01 เลย |
| L78745610-V1 | 2026-08-11 | RCB-EDC-KBANK | 7,500.70 | 1134-01 เต็มจำนวน ไม่มี 1135-01 เลย |

ทางทีมตรวจสอบแล้วพบว่า ในข้อมูลที่ interface ออกไป ExpectedReceived มีค่าถูกต้อง (เท่ากับ TotalAmount) แต่ **ActualReceived กลายเป็น 0** ทั้งที่ลูกค้าจ่ายเงินจริงแล้ว (ยอดที่ชาร์จบัตรจริงตรงกับ ExpectedReceived ทุกกรณีที่เช็ค) — ทางทีมเข้าใจว่าเมื่อ ActualReceived ไม่ตรงกับ ExpectedReceived ระบบ SAP จะบันทึกส่วนต่าง/ยอดทั้งหมดเข้า 1134-01 แทน

**เป้าหมายของบัญชี:** ต้องการให้รายการเหล่านี้บันทึกบัญชีถูกต้อง (เข้า 1135-01) **ตั้งแต่รอบแรกที่ interface เข้าไป ไม่ต้องมาปรับปรุงรายการ (manual adjust) ย้อนหลัง**

จึงอยากรบกวนสอบถามค่ะว่า:
1. ทางทีมควรแก้ไข script ให้ส่งค่า ActualReceived เป็นยอดที่ชาร์จจริง (เท่ากับ ExpectedReceived) แทนที่จะเป็น 0 ใช่หรือไม่คะ — ถ้าแก้แบบนี้ SAP จะบันทึกเข้า 1135-01 ถูกต้องเลยหรือเปล่า
2. มีเงื่อนไข/field อื่นที่ SAP ใช้ตัดสินใจเลือกบัญชี 1134-01 vs 1135-01 อีกไหมคะ นอกจาก Expected เทียบกับ Actual
3. รายการทั้ง 141 รายการที่ลงผิดไปแล้ว (บัญชีค้างอยู่ที่ 1134-01) จะต้องแก้ไขยังไงคะ — ต้องให้บัญชีปรับปรุงรายการเอง หรือมีวิธี resubmit ให้ระบบแก้ไขให้อัตโนมัติได้

ขอบคุณมากค่ะ ยินดีส่ง list เต็ม 141 รายการให้เพิ่มเติมได้ตามที่ต้องการเลยค่ะ
