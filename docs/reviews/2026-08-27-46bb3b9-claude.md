## What this does and why it's needed

`sp_evaluate_v3_unit2_magnitude` (DDL 063) requires both an active `v3_unit2_magnitude_config` row
and a prior successful `PASS` in `v3_unit2_magnitude_run` tied to a completed Units 2-5 archive —
on the very first run neither can exist, so the gate can never pass without a bootstrap path. DDL
099 breaks that circularity by registering the human-approved thresholds and a self-baseline (the
first run's own distribution compared to itself, trivially zero breach) in one atomic procedure.

## Replay/exclusivity guards (the actual "one-time" enforcement)

Three independent `ASSERT`s make this genuinely one-time rather than one-time-by-convention:
zero currently-active configs (line 43-47), the `config_id` not already used (line 48-51), and no
existing distribution/magnitude-result evidence for the chosen baseline run (line 62-69). All three
must hold simultaneously, so a second bootstrap attempt against either a live config or a reused
run ID fails closed before any write.

No BLOCK, no notes. This is ready to move to dry-run/deploy review once an actual pipeline run and
approved thresholds are available — deployment/CALL is correctly not authorized by this artifact.
