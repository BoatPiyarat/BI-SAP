## What changed

Delta `aae4e01` replaces the name-only push-subscription check with real configuration
validation, and additionally hardens two things the base review didn't ask for but are the same
class of gap.

## Verification

- **The required note is fully resolved**: when a push subscription with the expected name exists,
  the script now checks `subscription.topic` (must be the exact input topic, not just any topic),
  `pushConfig.pushEndpoint` (must equal `$($dispatcher.status.url)/dispatch` exactly),
  `pushConfig.oidcToken.serviceAccountEmail` and `.audience` (must be the push identity and the
  same endpoint), `deadLetterPolicy.deadLetterTopic`/`maxDeliveryAttempts` (must be the DLQ topic
  and exactly 5 attempts), and `ackDeadlineSeconds` (must be 600). This is exactly what my required
  note asked for — the subscription's *actual* delivery configuration, not just its name, is now
  the gate. Field names (`deadLetterPolicy.deadLetterTopic`, `pushConfig.oidcToken.audience`,
  `ackDeadlineSeconds`, etc.) match the standard Pub/Sub v1 REST schema.
- **A related bug the base version had, that I hadn't caught, is also fixed**: the original
  `push identity lacks dispatcher run.invoker` check tested `$dispatcherMembers -notcontains
  $pushServiceAccount`, where `$dispatcherMembers` was every member across *every* IAM binding on
  the service, regardless of role — so any unrelated role grant to the push account (not
  necessarily `run.invoker`) would have satisfied this check. The delta introduces
  `$dispatcherInvokerMembers`, filtered with `Where-Object { $_.role -eq 'roles/run.invoker' }`
  before collecting members, and checks against that instead — now genuinely verifies the *specific
  role*, not just membership in *some* binding.
- **Additional hardening beyond the required note**: rejects `allAuthenticatedUsers` alongside the
  existing `allUsers` check (broader unauthenticated-adjacent principal); the watchdog scheduler
  readiness check now validates cadence (`*/2 * * * *`), time zone (`Asia/Bangkok`), target URI/
  HTTP method, and OAuth service account — not just existence and `PAUSED` state as before.
- **Independently re-ran the corrected script against the live project**: identical
  `safety_passed=true`, `rehearsal_ready=false`, and the same three readiness blockers as the base
  review — the new deeper checks correctly short-circuit (via the `else` branches guarded by
  `Count` checks) since none of those resources exist yet, so nothing errors on missing data.
- **`git diff --check aae4e01^ aae4e01`**: clean, no trailing whitespace.

## Verdict

PASS. The required note from the base review is fully resolved, plus the delta independently
catches and fixes a same-class role-scoping bug in the existing `run.invoker` check that the base
review missed. No mutation, IAM change, or production action was performed by me in this review.
