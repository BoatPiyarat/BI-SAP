## `execution_health` CASE logic

Traced all five branches against the underlying evidence columns: staleness is checked before
completeness (so an old-but-technically-complete run still reads `STALE`, which is the right
priority for a freshness dashboard); `FRESH` requires positive same-run evidence from either the
healthy-zero or LOAD-commitment path, matching the stated design intent; `EVIDENCE_INCOMPLETE` is a
safe catch-all for any future/unexpected evidence combination rather than a silent default.
